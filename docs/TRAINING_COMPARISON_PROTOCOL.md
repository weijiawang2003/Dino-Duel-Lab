# 本轮实训比较方案：普通 PPO 与 JEPA 辅助 PPO

固定日期：2026-10-25。

这份方案在训练已经启动、看过初期训练日志和小规模游戏诊断后固定，约束后续的最终比较。它不是声称在任何数据出现之前完成的外部预注册。最终测试种子不参与超参数、检查点、推理模式或手工基线的选择。若后续偏离本方案，报告应标明偏离内容与原因。

## 1. 本轮要回答的问题

在同一款结构化状态双人 Dino 游戏、相同基础跑跳策略和相同环境交互预算下，给 PPO 的攻击／价值编码器增加一个动作条件的下一步 latent 预测损失，是否改善攻击策略的实际对战成绩？

`baseline` 是普通 masked PPO，`jepa` 是同一个 PPO 加辅助目标。两者的基础跑跳网络均冻结。因此本轮测量的是攻击策略，不能据此声称跑跳、防守或通用游戏能力得到改善。

## 2. 固定训练设置

主比较使用 `configs/trained_strength.json`，通过项目配置加载器继承共同的 `cpu.json` 游戏规则。以每个输出目录中的完整 `config.json` 和 checkpoint 内配置为准。

| 项目 | 两种方法共同设置 |
|---|---|
| 训练种子 | 11、23、47，逐种子配对 |
| 报告检查点 | 最终 update 300，不按最终成绩选择中间检查点 |
| 每次更新 | 8 个环境，每个环境 256 个 joint steps |
| 每次训练的交互预算 | 614,400 joint environment steps |
| 六次主训练合计 | 3,686,400 joint environment steps |
| 编码器 | 两层 Tanh MLP，hidden 128 |
| 基础跑跳 | 同一个 bundled BC runner，冻结 |
| 奖励 | 终局胜 +1、负 −1、平 0；无额外 shaping |
| GAE | gamma 0.999、lambda 0.995 |
| Actor 优化 | `decision_only_actor=true`，仅合法动作不止 wait 的步参与攻击 actor 目标 |
| Critic / JEPA | 使用全部符合条件的 learner transitions |
| PPO | 每次更新最多 4 epochs，minibatch 256，学习率 0.0003，entropy 系数 0.015，KL 上限 0.03 |
| 自博弈 | 当前策略与历史池混合；历史对手概率 0.35，池容量 8，每 25 updates 存一次快照 |

已经对六个 `initial_policy.pt` 做逐 tensor 检查：每个配对训练种子的 encoder、attack head、value head、runner 初始权重完全相同；游戏规则、训练配置和 runner SHA-256 也相同。创建 JEPA 额外模块后重置动作采样 RNG，使辅助模块初始化不改变最初的采样种子。两种方法开始更新之后的策略、轨迹和随机数消耗可以分岔，不要求它们持续经历相同轨迹。

另有 `baseline_random`、seed 23 的固定随机对手训练，属于强度诊断。它的训练对手分布与主实验不同，不能替代某个 self-play baseline，也不能与主 JEPA 成绩混合后宣称方法优势。

## 3. 预算公平性的具体含义

这里匹配的是 joint environment steps、更新次数和初始 acting backbone，不是完全匹配所有资源。

| 参数数量 | 普通 PPO | JEPA 辅助 PPO |
|---|---:|---:|
| Acting 参数（含共同冻结 runner，不含 value head） | 30,024 | 30,024 |
| 可训练参数 | 24,198 | 59,270 |
| 保存的全部模型参数（含冻结 runner 和 EMA target） | 30,153 | 88,649 |

JEPA 额外训练 predictor，并维护 EMA target；这些模块不参与实际选动作。最终报告应列出每次训练的实际 `agent_steps`、有效攻击决策数、优化 minibatch 数和训练耗时。历史对手替换一侧后只收集另一侧的 learner transitions；不同策略的局长会改变分配结果。KL 早停也会改变优化次数。所以相同环境步数不能表述为相同 learner 样本数、相同 FLOPs 或相同墙钟时间。

本轮多训练进程并行运行，墙钟时间包含共享 CPU 的资源竞争，只作为实际成本记录，不作为严格的独占硬件速度基准。

## 4. 推理模式在最终测试之前固定

**主分析：双方 learned attack 都从合法动作的 masked softmax 采样，motor 使用共同 runner 的 argmax。** 这与冻结 runner 训练时的行为形式一致。每个逻辑策略使用独立、可复现的随机数生成器；换座位时保留它的身份种子。

**次要部署分析：attack 使用 argmax，motor 仍使用 argmax。** 两种方法必须使用共同模式比较，不把某方法最好的 sampled 结果与另一方法最好的 greedy 结果拼接成主比较。也不依据最终测试表现切换主模式。

验证集可用来选择给用户展示的回放、部署推理模式或附加部署检查点。此类选择必须另外标记；主方法比较始终使用每个种子的 update 300，不能用验证后挑出的单个最好模型代表整个算法。

## 5. 数据划分和最终对局

训练环境种子位于 `[0, 2**31)`。本轮脚本定义：

| 用途 | 种子范围 |
|---|---|
| Validation | 从 `2**33` 开始；默认 12 个种子 |
| Final | `2**34` 至 `2**34 + 49`，共 50 个种子 |

每个环境种子都交换物理座位再打一局。因此每个固定 matchup 有 50 对、100 局；同种子 JEPA 对 PPO 的三组 head-to-head 合计 300 局。每对的两局是一个配对单元，不能当作两个完全独立的随机样本。

所有最终对局使用同一份原游戏配置和同一个 BC runner。不得为了改善某个模型成绩而更改初始金币、障碍间距、速度、可达性 gate 或局长。完整结果应保留逐局 CSV、摘要 JSON、模型 SHA-256、规则和评估代码 SHA-256。

最终测试用于报告已经确定的模型，不用于延长训练、选择最优训练种子或修改算法。最终结果若不理想，先如实报告；后续改进需要标为另一轮实验，并使用新的未参与选择的测试种子。

## 6. 固定对手和强攻击基线

主固定对手集合为 `bc:random`、`bc:aggressive`、`bc:save`、`bc:burst`。它们使用与 learned policy 完全相同的冻结 BC runner。`bc:none` 可以作为额外的纯攻击成功率检查，不混入四个竞争性对手的主宏平均。

`bc:burst` 是在小规模游戏诊断中发现、在最终测试前冻结的手写强基线，亦称双仙人掌连招：

1. 从公开 observation 的钱包比例和公开 wallet cap 读取金币。
2. 储存到至少两颗 small cactus 的公开价格后进入连发状态。
3. 在随后每个 `mask[1]` 合法的购买机会各买一颗 small cactus，买满两颗后重新存钱。
4. 每局重置内部连发计数。

它只使用公开 observation、合法动作 mask 和共同 runner，不读取模拟器隐藏状态、未来动作或搜索得到的答案。它不是学习成果，不能作为“训练出的模型”的替代品。加入它的目的是避免只通过容易的 `aggressive` 或 `save` 对手就声称模型已经很强。

## 7. 指标与统计单元

主直接比较是 matched-seed head-to-head：JEPA seed 11 对 PPO seed 11，依次对 seed 23、47。每局分数为胜 1、平 0.5、负 0；先平均每个环境种子的两座位分数，再计算每个训练种子成绩，最后对三个训练种子等权平均。

固定对手成绩用于检查能否迁移到共同的外部对手。逐个列出三次训练对四个对手的胜／平／负和分数，并报告四个对手等权的宏平均。方法差值采用相同训练种子、相同环境种子、相同对手的配对比较，不只展示最高的一次训练。对相应 `initial_policy.pt` 的前后比较属于学习是否有效的辅助证据。

不确定性至少分两个层次表达：

- 固定 checkpoint 的区间重采样完整环境种子对，说明这两个确定策略对不同评估随机性的敏感程度。
- 方法层面的探索性区间使用**交叉 bootstrap**：重采样训练种子行，同时抽一套共同的环境种子列，并将这一套列用于全部选中的训练行。每个环境列保留完整换边对局及 JEPA/PPO 配对关系；固定对手宏平均时保留预先确定的四个对手等权结构。这样保留所有训练模型共用同一批评估环境及策略随机种子所产生的相关性。

只有三个训练种子，无法可靠刻画训练结果分布的尾部。300 局 head-to-head 不等于 300 次独立训练。应完整列出三组结果，不用狭窄的逐局区间掩盖训练种子之间的波动。多个对手与两种推理模式的区间是探索性描述，不能从其中挑一个较好的结果当作预先指定的总体显著优势。

辅助行为指标包括局长、平局比例、攻击类型和购买数量。`mean_episode_return` 对零和双方求平均会接近零，不作为学习进展或强度指标。

### 统计复核后的修正记录

2026-10-25，首次最终比较生成后，独立复核发现原来的 nested bootstrap 为每个抽中的训练组独立抽环境种子列。这不符合本实验中所有训练组共享同一批环境种子的交叉设计，会破坏组间共享测试随机性的相关。对完全相同表现的多个训练组，它还可能把重复测试条件误当成独立环境证据，使区间变窄。

因此修正为上述训练行与共享环境列的交叉重采样，并增加重复完全相同训练行不应缩小环境不确定性的回归检查。此次变更是对同一批原始数据的统计分析修正；训练、检查点、评估种子、推理模式、对手及逐局计分规则不变。它发生在看到首版结果之后，**不属于预先注册的统计方法，也不声称外部预注册**。原来匹配最终 update 和主推理模式的约束仍然有效。

修正后的区间写入 `crossed_ci95`；为兼容已有 JSON 消费者，`hierarchical_ci95` 保留为同值兼容字段。结果同时新增 `bootstrap_design="crossed_training_and_shared_environment_seeds"`，并由 `resampling_unit` 准确说明计算方式。正式报告采用修正后的交叉 bootstrap 区间；原区间不能继续作为稳健优势的证据。三个训练种子的样本仍然很小，修正后的区间也应视为探索性估计。

## 8. JEPA 实现及辅助损失的解释边界

这里的 JEPA 是 **动作条件的下一控制步 latent 预测辅助目标**：online encoder 编码当前公开状态，predictor 接收本步双方实际执行动作，预测 stop-gradient EMA encoder 编码的下一状态。双方实际动作只在转移发生后用于训练，不提前暴露给 acting policy。

在本轮 `dt=1/60`、`action_repeat=4` 下，预测跨度是 **1/15 秒**，不是下一次购买机会，更不是整条攻击连招的未来。该模型没有多步 latent rollout、搜索、MPC 或推理时规划，也没有使用官方 I-JEPA/V-JEPA 预训练视觉模型。结论应限定为“此实现中加入这种辅助损失后的效果”。

报告 JEPA 的 `prediction_loss`、`variance_loss` 和 `latent_std` 随训练的变化。接近零的表示方差是明显警报；较高的平均 `latent_std` 只能排除简单的全常数表示，不能证明维度独立、有效秩足够或表示对决策有用。相邻 1/15 秒的状态本就变化较小，预测损失下降也不能独立证明模型学会了长期因果关系或攻击规划。

本轮没有完成同预算的 shuffled-target、无 variance penalty、精确训练参数／FLOP 匹配等额外消融。若 JEPA 成绩较好，证据支持这一整套辅助训练配置在本任务和预算下有效，仍不能完全分离未来预测、正则化、额外参数或额外优化计算的各自贡献。若 JEPA 没有较好，也不能否定更长预测跨度、其他表示学习方式或官方 JEPA 模型。

## 9. 最终报告必须能核对的事项

- 六个主 checkpoint 均达到 update 300，并列出实际交互、learner 和优化计数。
- 三个训练种子的全部成绩；主 sampled 与次要 argmax 明确分开。
- 四个固定对手的完整表，包含手写 `bc:burst`。
- matched-seed head-to-head 的完整胜／平／负与训练种子间差异。
- 实际训练成本、参数数量差异、冻结防守和一步辅助预测的限制。
- 已保存的模型、原始对局记录和可离线查看的回放；演示回放不代替完整成绩。

如数据只支持“模型学会了一些攻击策略”，就报告该结论；如结果不足以区分 JEPA 和普通 PPO，就明确说本轮没有建立方法优势。
